# 引き継ぎ：ピアノ曲の難易度別MIDI自動生成（次セッションはPCローカルで実行）

## 目的
難しいピアノ曲（例：モーツァルト「トルコ行進曲」）を最終的に弾けるようになるために、
原曲MIDIから **やさしい段階 → 原曲** の練習用MIDIを自動生成する。
方針は「難しい原曲を要素（右手旋律・左手低音・左手和音・オクターブなど）に分解し、1段階ごとに1要素ずつ足す」逆算方式。

## 現状（完了していること）
- ツール `midi_levels/` をブランチ `claude/midi-difficulty-split-oez8jk` にコミット・プッシュ済み。
- 実行：`python -m midi_levels 曲.mid [-o 出力先] [--beats-per-bar 2] [--min-bpm 125] [--max-bpm 176] [--no-musicxml] [--no-plot]`
- 出力：`<曲>_hands.png`（左右色分けピアノロール）、`<曲>_quantized.mid`、Lv1〜Lv6 の `.mid` と `.musicxml`、`report.json`。
- 依存：`mido pretty_midi numpy matplotlib music21`（`midi_levels/requirements.txt`）。

### 段階の定義（ユーザーと合意済み）
| 段階 | 右手 | 左手 |
|---|---|---|
| Lv1 | 旋律のみ（最上声、オクターブは下の音に統一） | なし |
| Lv2 | 旋律のみ | 各拍の最低音 |
| Lv3 | 旋律のみ | 各拍：低音＋5度以内の1音 |
| Lv4 | 旋律のみ | 8分刻み：低音＋5度以内の1音 |
| Lv5 | 旋律のみ | 原曲どおり |
| Lv6 | 原曲どおり | 原曲どおり |

当初は4段階だったが「Lv2とLv3の差が大きい」との指摘で6段階に分割した。

## 入力データについて（リポジトリには入っていない）
- 著作物のため、MIDIはコミットしていない。ユーザーのPCにある次の2ファイルを使う。
  - `Turkish_March_Mozart … Piano_CANACANA_v3.mid`（本命）
  - `7_levels_of_Twinkle_Twinkle_Little_Star … v3.mid`（参考）
- どちらも **音声からの自動採譜MIDI**：1トラック・ch0、テンポ120固定（実際は♩≈143）、タイミング非量子化、ペダル情報なし、ベロシティはばらばら。
  - 音の長さにペダルの響きが含まれるので、「同時に鳴っている音の数」は和音の音数として使えない。
- キラキラ星の7段階版は、最初から段階的なアレンジなので自動生成は不要とユーザーが確認済み。

## 処理の中身と決定事項
1. **左右の手の分離**（`hands.py`）
   - ピッチ分布は二山（左手側の山はA3・E3、右手側の山はA5・E5・B4）。境目にE4・G#4があるため、固定の分割点では約5%の音が逆の手に入る。
   - そこで、和音ごとに分割ピッチをViterbiで求める（音の少ない所を通る経路を選び、片手のスパンが14半音を超えるか5音を超えると罰則）。
   - ユーザー指摘を受け、境界線を ±1秒の中央値で平滑化した。境界が一瞬だけ跳ねて、反対の手の音が割り込むのを防ぐため（要望済み・確定）。
   - 結果：右手1,467音・左手1,213音。右手でC4未満は0音、左手でG4超は1音。
2. **拍の推定と量子化**（`beats.py`）
   - 採用していない方式：
     - librosaの拍推定：テンポ一定の前提のため、区間の途中で半拍ずれた。
     - 16分音符を1音ずつ追う位相同期：16分単位で拍を取り違えた。
   - 採用した方式：8分音符の刻みを動的計画法で求め、周期の緩やかな変化を許す。それを2等分して16分のグリッドを作る。
   - 小節の頭（ダウンビート）は、2小節ごとのブロックで左手の最低音の位置から決め、切り替えに罰則を付ける。
   - 結果（トルコ行進曲）：213小節、♩≈143、音の出だしのずれは中央値5ms。
   - 小節の頭を補正した箇所は 58.9秒・70.2秒・111.1秒。前後1小節は長さが半端な可能性がある。
   - 冒頭の音型は楽譜と一致を確認済み（右手「C5 休 D5 C5 B4 C5 / E5 … F5 E5 D#5 E5」、左手「A3 / C4+E4 8分刻み」）。
3. **段階の生成**（`levels.py`）
   - 旋律の抽出：最上声を取り、オクターブは下の音に統一する。交互に弾くオクターブ（16分）は1音にまとめ、前後から1オクターブ外れた音は戻す（採譜でオクターブの片方が抜けている対策）。

### リグレッション基準（トルコ行進曲、既定オプション）
各段階の音数：Lv1=1030, Lv2=1408, Lv3=1550, Lv4=2015, Lv5=2242, Lv6=2677。

## PCローカルで試すべきこと（優先順）
1. **環境構築と再現**：`pip install -r midi_levels/requirements.txt` → トルコ行進曲で実行し、上のリグレッション基準の音数と一致するか確認する。Windowsでの文字化け・パス（日本語ファイル名）も確認する。
2. **MuseScoreで確認**：各Lv の `.musicxml` を開き、楽譜として読めるかを見る（音部記号、連桁、休符の細切れ、拍子）。
   - 特に小節の頭を補正した箇所（58.9秒・70.2秒・111.1秒付近。B→C区間のつなぎ目とA主題の再現の頭）。
   - MuseScore CLI（`MuseScore4.exe -o out.pdf in.musicxml`）でPDF化できれば、ツールに組み込みを検討する。
3. **PM2Sを試す**：ローカルなら zenodo / PyTorch に接続できるはず。
   - `git clone https://github.com/cheriell/PM2S` → CPU版のtorchを入れる → `RNNHandPartProcessor`（左右の手）と `RNNJointBeatProcessor`（拍）を同じMIDIに適用する。
   - 自作の手の分離・拍推定と結果を比べ、良ければ置き換えるか、オプションで選べるようにする。
4. **ユーザーに実際に弾いてもらい**、段階の差が適切か聞く。想定される追加調整：
   - Lv4→Lv5 の差（コーダの左手16分の分散和音 A3-E4-C#4-E4、B部分の4音和音）が大きければ、間に段階を足す。
   - 段階ごとの練習テンポ（例：Lv1〜3 は ♩100〜120）を書き出すオプションを足す。
   - 区間（A主題／B／Cエピソード／コーダ）ごとに分割したファイルを出す。
5. **採譜の誤り対策**：左手の和音に混じったF4（例：C4+E4+F4）、130小節目のA#4など。和声的に不自然な短い音を除くフィルタを検討する。
6. **汎用性**：キラキラ星は `--beats-per-bar 4 --min-bpm 60 --max-bpm 110` で通るが、4分音符が8分音符として記譜される（音価が半分になる）。テンポ範囲の自動推定や、3/4拍子への対応を検討する。
7. 合成MIDIを使った最小限のテスト（手の分離・量子化・段階生成）を追加する。

## 参考
- 曲の構成（調の推定で検出）：A主題 イ短調（5–45秒）→ B イ長調（45–59秒）→ C 嬰ヘ短調（59–98秒）→ B（98–111秒）→ A主題（111–137秒）→ B＋コーダ イ長調（137–183秒）。
- 難所：
  - 右手：A＝16分のターン音型、B＝オクターブの旋律、C＝途切れない16分音符。
  - 左手：A・C＝低音＋2音の8分刻み、B＝4音和音＋オクターブ、コーダ＝16分の分散和音。
- 解析に使ったスクリプトのうち、拍推定の試行錯誤版（librosa版・位相同期版）はクラウドの作業フォルダにしか無く、消えている。採用版は `midi_levels/` に統合済み。
